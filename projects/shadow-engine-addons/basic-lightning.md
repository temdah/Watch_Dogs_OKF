retained; they do not imply every historical candidate passed its runtime gate.

# What TFoWC2 changed
The world's single `lightningflashgeneratorLightning` reference selects
`TFoWC/Moon.Shadows` (`808323553`, key bytes `E1092E30`) instead of retail
`Storm.Lightning_A` (`1969453363`, key bytes `33796375`). Storm A remains in
the preserved TFoWC2 library. This is a selector, not an independent on/off
toggle for both systems.
Moon.Shadows has zero sky-curve output, directional HDR intensity `0.012`,
fixed intensity 1, zero intensity noise, and silent `FFFFFFFF` sound IDs.
Storm A has directional HDR intensity 0, a nonzero eight-knot sky curve,
and native strike/thunder IDs. Do not change the moon record or world selector.

# Current implementation and recovered boundaries (2026-09-04)
The complete scheduler disassembly confirms output R9 is saved in RDI, used
only for the scalar store at `0xA25315` to `+0x364`, then discarded as EDI
becomes a loop index. v2.1.8 passes a private 0x368-byte output buffer. Moon
output is never passed to this scheduler or temporarily overwritten.
`0xA077B0` calls vector retirement `0xBA290`. The latter invokes element
cleanup, frees non-inline backing through `0xEE860`, and zeroes the pointer and
size metadata. The native environment destructor uses the same vector cleanup
before releasing its state. The candidate owns a static 0x30-byte state, calls
native retirement before reinitialization, and never frees native moon state.
Retirement alone does not reset clocks: native construction is repeated after
retirement, preserving its initial eight-second wait and original scheduling.
At `0xA5395A`, the native curve coordinate comes from the sky context `+0x110`;
`0xA542C3` forwards this coordinate to the selected lightning curve evaluator.
It is NOT the incoming third sky argument. The accepted v1.0.7 sidecar passed
that third argument to its curve, so v2.1.14 deliberately restores the accepted
behavior rather than claiming exact retail curve selection. v2.1.8 read the
current publisher context's `+0x110`. Its precise
semantic name is not required or claimed here; the native dataflow is confirmed.
The sky function's first selected entry overwrites sky RGB via `0x8DA480` at
`0xA540E1`; later entries blend. Native lightning adds to `+0x108/+0x10C/+0x110`
at `0xA54306..0xA54333`. The candidate adds only those three floats once during
the owning sky invocation before `0xA15180`, preserving the original output
pointer and all subsequent consumers. It requires at least one selected entry.
RGB stays in native output until native recomputation; it is not restored too
early after publication, replaced by a stack buffer, or accumulated by Addons.
Moon selector/state and directional fields remain untouched.
`0x25CFED0` is NOT read-only even with its third argument zero: it clears a dirty
bit, allocates/refreshes output and updates map metadata. v2.1.8 never calls it.
It copies rain at resolved output `+0x2A0` only from an already-materialized,
clean slot: map `0x36B6AA0`, key index `0x36B6B90`, slot table via map `+0x90`
and its first pointer, dirty metadata via `+0xC8`, 16-byte metadata stride,
dirty bit0 at `+0xB`, 8-byte output pointer stride. Index cap4096 and repeated
reads reject dirty/missing/changing inputs. This is a static layout mapping,
not a general synchronized engine lookup API.
Loaded exact-key lookup identifies Moon and Storm A. Selected Moon must equal
the loaded Moon record. Record `+0x14/+0x18` remains raw metadata, not assumed
key identity. Storm settings and all native curve knots are copied and checked
before native calls, with 16-byte-aligned owned knot storage. No borrowed
record, curve, output or environment pointer is retained for later dereference.
Pointer-valued scene tokens are used only for comparison.
The prior rain/third-argument hysteresis is retained (entry0.18/0.78,
exit0.08/0.65). Historical success supports this gate, but calling the third
argument a fully proven physical cloudiness measure would overstate evidence.
Its current live coverage must be tested. The separate native lightning-update
enabled argument is not intercepted; cutscene/scripted-weather behavior remains
unvalidated. v2.1.8 passed the selected generator's sound-enable flag into the
separate storm scheduler. v2.1.9 instead passes true for private storm audio;
copied native sound IDs, timing and mixer behavior remain unchanged. No
positional audio or bolt is added.
# Lifecycle, compatibility and acceptance limits
One shared sky hook dispatches the feature. TLS bounds publication to that
invocation; a nonblocking owner guard excludes overlapping/nested mutation.
The publication detour is an optional signature-gated extension. All ten byte
gates are checked before mutation; TLS/allocation/protection failures are tested,
including restoration of original publication bytes. Published trampolines and
TLS remain process-resident after a late failure for possible in-flight calls.
These short guards identify the captured layout, not all storefront builds.
Live hook installation is not a thread-suspended atomic patch operation.
Weather exit, disable, invalid data/delta, a callback gap over one second,
scene-token change, or a frame with no publication retires private pulses.
Menu shutdown requests disable; retirement runs on the next owning sky callback.
If no callback follows, OS process teardown reclaims private pulse backing.
No game pointer must be accessed later to perform that retirement.
Offline tests use actual control/copy code with native providers mocked; they
prove isolation and failure handling, not live native ABI/lifetime or visuals.
Required manual acceptance: automatic storm start, continued clear-night moon shadows,
natural storm flashes and sound, storm-to-clear without stray flashes,
Disable and scene/reload behavior.

# Explicit pulse admission with native animation

The event-controlled internal path can retain native temporal animation instead
of replacing the scheduler output with an authored envelope. Static inspection of
the following pinned Disrupt builds establishes the same admission-clock layout:

| Build/profile | Scheduler RVA | Owned state layout |
| --- | --- | --- |
| Global / supported-04DF | `0xA24DE0` | wait float+0, elapsed float+4 |
| A4EE/Shev unpacked / a4ee-signed-variant | `0x5EC980` | same verified layout |
| VMPless / vmpless-1.06 | `0x602F80` | same verified layout |
| Complete Edition / complete-edition-1.06.329 | `0x1A40580` | same verified layout |
| Asia/Miru / asia-miru-1.06.329 | `0x668CE0` | same verified layout |

Input hashes, mapped-image identity and exact instruction evidence are retained
in the cited admission proof. This is static evidence, not five-build gameplay
acceptance. Full pinned function bodies and independent comparison/add/store/branch
checks gate the layout. Immutable profile metadata owns the common clock offsets.

Each native call advances elapsed+4 by dt and admits one pulse only when this
exceeds wait+0. The pulse vector is state+18/count+20, its animation clock is+10,
and the native random seed is+28. Pulse duration comes from settings+30/+34;
intensity from+38/+3C; per-update noise from+40. Native code combines its centered
parabolic envelope with randomized noise, sums live pulses and clamps output+364.
The retained authored StormA record has duration0.5-2s, intensity0.1-0.4 and
noise ratio1.2. An envelope's duration is not one steady visible white flash.

A mod-owned admission policy sets **only its own private state's** wait=0 and
elapsed=1 to admit a requested strike. It then sets wait=FLT_MAX and elapsed=0
to suppress unrequested random additions. The actual native scheduler still
allocates, animates and expires pulses, preserving loaded duration/intensity/noise
and the existing native sky curve. One frame advances dt once; extra simultaneous
admissions use zero dt. The native seed is not replaced per event. Public random
scheduling remains a separate unchanged policy when no event driver is configured.

The serialized shared owner lends a step callback and validated settings for one
update only. The policy retains neither the callback context nor engine pointers.
Cancellation requests reset/construct on that owner; the Lua/menu thread never
frees native pulse storage. Weather/context loss uses the existing serialized
retirement. Moon state/settings/selector remain untouched. In this internal policy,
native pulse audio is suppressed because the existing mod-owned distance/343
thunder queue owns submission and still respects the native audio-enable gate.

Offline fixtures cover exact requested admission count, no random admissions,
single dt advancement, unchanged settings/seed and deferred reset; the compiled
Lua/native transport still owns meshes, windows and delayed audio. Complete native
profile checks pass for all five images. Reusing a native routine does not prove
its new calling context in game: renewed runtime testing is required for this
changed boundary. The prior short custom white pulse was rejected by the human
observer; that report does not establish acceptance of this replacement.
